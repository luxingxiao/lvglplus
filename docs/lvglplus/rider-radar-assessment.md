# Rider Radar 向 LVGL Plus 迁移可行性评估

评估日期：2026-10-16。结论针对软件原型的功能迁移，不代表已经完成迁移或设备验收。

> 后续进展：本报告评估的是下表固定的 0.2.0 提交。针对其缺口，当前工作树已补充 [通用声明式能力](declarative.md) 和独立验收示例；见 [新增验证记录](verification-declarative.md)。这不代表原应用的完整迁移已经完成。

## 结论

**可以使用当前 LVGL Plus 作为复刻平台，但完整效果需要“XML 页面 + 自定义 C 图形控件 + C 业务模块 + 应用运行时接入”。仅用当前 XML、Studio 拖放和内置 MVVM 表达式，无法完整实现该应用。**

当前版本适合启动验证和迁移，无需先补齐整个通用 UI 平台。不过，现成 custom 工厂不等于完整业务插件：上下文访问、应用时钟、命令路由和状态传递必须显式实现。若要求任意开发者只修改 XML 就能构建同类雷达/组队应用，应先扩展框架。

建议先以 Linux/桌面与 WASM 为目标，保留 840×480 视觉和原有交互语义；具体 MCU 作为后续独立移植任务。

## 原应用实际范围

原项目已经是 **LVGL 9.2.2 的 C 应用**，不是等待转换的 Web 页面。程序分为独立 840×480 仪表和 Python/HTML Web 调试台；`model.c` 提供模拟世界。

- 主仪表：大号数字车速、时间、天气、胎压、温度、电量、里程、功率条和双曲线。
- 车友雷达：4–8 个候选、扫描周期、角度与拖尾、匿名/已识别标记、距离、目标选择、打招呼、筛选与可发现开关。
- 组队骑行：10 人世界、3 个观察角色、2 秒快照、相对坐标路网、自动缩放与聚类、航向、成员电量和状态。
- 业务交互：6 条快捷消息、错路/低电/离线/等待/回队等剧情、菜单焦点、方向键/确认/返回、滚轮与触摸。
- 联调：带序号确认的控制命令、状态 JSON、5 Hz 原生帧截图；Web 刷新不重置仪表。

`main.c` 951 行、`radar_view.inc` 70 行、`team_view.inc` 320 行、`model.c` 325 行。行数只用于定位迁移范围，不用来估算完成比例。

地图来自项目内置的米制路线和投影算法，不是通用在线地图服务；现有车友和车联网数据也都是模拟。无需为复刻已有原型额外引入地图 SDK 或真实云服务。

## 决定实施方式的关键缺口

### 1. 动态图形与属性绑定

当前内置为 panel/text/button/bar/slider/arc/switch/image，加 custom。绑定只有 text/value/checked/hidden/color/quality；动画只支持 x/y/opacity/value，并不等于可将坐标和航向绑定到实时模型。

本次编译探测结果：

```text
custom + value binding : success
<line .../>           : WIDGET / Unknown widget line
rotation="45"         : PROPERTY / Unknown property rotation
bind property="x"     : BIND_PROPERTY / Unknown binding property x
```

自定义控件的 `custom.*` 属性主要是静态初始化；普通 value 绑定会转为 int32 文本传给工厂。不能将它当成任意浮点属性、集合或完整世界快照的动态绑定接口。

### 2. 业务生命周期与预览闭环

`lvp_widget_factory` 只有 `create(parent)` 和 `property(object,name,value)`。标准预览的 `context` 是内部静态状态，custom 工厂没有直接获取该 context 的公开参数。默认 preview tick 也不会自动调用项目的 `world_step`，没有项目命令处理器时业务命令会失败。

生产应用可以自己持有 context，注册命令处理器并管理时钟。为了让 Studio/WASM 得到同样行为，建议增加兼容的项目应用生命周期接入：初始化时注入 context，统一 tick，注册命令，销毁与重建后重新挂载。也可先实现项目专用 WASM 宿主/桥接，但必须明确维护两条构建路径，不能声称仅列出 `native.sources` 就完成集成。

将整个旧仪表包进一个 custom 控件是可用的短期显示方案，但其内部节点无法完整接受 Plus Inspector、节点检查、绑定可视化与编辑，因此只适合作为对照验证，不宜作为最终平台范例。

### 3. 状态结构与容量

当前上限为 256 信号、512 个 IR 节点、单字符串 255 字节；字体注册表和 custom 工厂各 16 项。原程序创建了多个字号的中西文字体，不能无规划地逐项注册。建议按实际可见文本裁剪字体组合，custom 内部字体按组件管理。

`World` 包含实时成员、显示快照、雷达候选和消息数组。完整字段逐项展开可能超过信号预算，应先列字段清单。仅将车速、电量、选中项、模式等公共字段放进 Plus Model，雷达/地图采用固定容量强类型视图快照；禁止用一个超长 JSON 字符串信号绕过类型系统与长度上限。

快照更新应具有版本号和原子提交语义，保证 10 人坐标与角色来自同一快照。连续状态可以合并；快捷消息和命令确认应作为事件保序，不能因队列合并而丢失。

### 4. 几何与模拟计算

原实现含 sin/cos/atan2/hypot、路线插值、自动缩放和聚类。Plus 表达式 VM 当前是算术、比较、逻辑和条件执行，不支持这些数学函数、循环和集合。建议将物理与领域计算继续放在不依赖 LVGL 的 C 模块，将像素投影和绘制留在适配/控件层。

### 5. 版本、字体和资源

原项目固定 LVGL 9.2.2，Plus 固定 9.5.0。绘制描述符、变换、线段、字体和截图接口需编译核对，并建立新的受控视觉基线。原代码还包含针对 9.2 线段问题的去重点逻辑，升级时应验证，而不是盲目删除。

原项目依赖 FreeType 动态加载本机字体；Plus 默认预览配置没有该字体环境，应转换为固定 C 字库或提供一致的字体后端。原项目的 Arial Narrow 不随仓库分发，不应假设所有机器已有该字体。迁移复用原源码和素材前也需确认项目授权范围；本评估未复制原项目源码或素材。

## 推荐结构与数据流

```text
模拟世界 / 回放 / 后续真实车辆与车联网数据
                    │
          RiderApplication（纯 C）
       World + 状态机 + 命令确认 + 时钟
          │                       │
  Plus 标量 Model          版本化只读视图快照
          │                       │
  XML 基础仪表与菜单        radar / team-map / trend
          └───────────┬───────────┘
                 Plus LVGL 适配
                   LVGL 9.5
               WASM / native / 设备
```

- 语义输入统一为 up/down/left/right/confirm/back 等动作；键盘、触摸、把手总线和调试台分别适配。
- 模拟世界只有一个；切换角色仅改变观察视角，不重建世界或重置消息。
- 模型时钟、扫描采样和 2 秒团队快照分别管理；暂停和倍速不能只改变 UI 动画。
- 页面热更新保留兼容 Model；非 Model 的 World/快照状态须单独定义保留和重挂载策略。
- 数据协议层不保存 LVGL 指针；custom 控件仅消费展示状态，不承担总线或云通信。
- 生成 C、WASM 和包放在 `.lvglplus/`，业务 C 与 XML 放在用户工程目录。

建议拆成基础 XML 页面、trend、radar、team-map 三个自定义图形组件，以及一个独立应用服务。具体控件边界可在首个垂直切片后调整。

工作量仅作初始规划：一名熟悉 C/LVGL/TypeScript 的工程师，复用已获授权业务模块、无新协议且不含真机时，A 约 3–5 个工作日；A–C 合计约 15–25 个工作日。纯 XML 通用化、复杂设计工具和具体硬件不在该区间。应在 A 完成后根据绘制兼容性、生命周期接入和视觉差异重新估算；不是交付承诺。

不能用原项目曾经通过的截图代替 Plus 迁移结果。固定字体、LVGL 配置、时钟、模拟种子和视角后，比较对象状态与图像；LVGL 升级造成的差异应审阅记录，不能直接更新基线掩盖错误。

## 性能与硬件边界

按当前 `lvp_ui_create` 实现，840×480 ARGB8888 framebuffer 为 1,612,800 字节，32 行绘制缓冲为 107,520 字节，合计约 **1.64 MiB**，尚未计入 LVGL 对象、字库、状态、图层、WASM heap 和浏览器 Canvas。50 次/秒完整 framebuffer 传输仅像素量就约 80.64 MB/s，但这不是实测带宽或帧率。

设备可通过 `lvp_ui_attach` 使用外部 display 和驱动缓冲策略，不意味着所有 MCU 都需要上述 PC framebuffer；雷达透明混合、变换和字体的实际开销仍需在目标硬件测量。原应用主循环约 20ms、截图 200ms 是调度设置，不能当作已测 50 FPS 或 Plus 性能保证。

## 本次检查与后续回归的区别

本次只新增评估文档，未修改运行行为、未进行应用迁移，因此没有重跑整套 Plus 测试。

实施时按仓库约定执行 `pnpm test`、`pnpm test:c`；涉及共享编译器或渲染器执行 `pnpm build:wasm` 和 `pnpm test:render`；自定义控件和字库还需 `pnpm test:extensions`。只有修改 DBC 相关能力才要求追加 `pnpm test:dbc`。另外新增 Rider 专用模型、命令、角色、快照、热更新、视觉与输入测试。
